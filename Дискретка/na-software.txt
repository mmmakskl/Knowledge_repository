Программа-интерпретатор для моделирования вычислений
по нормальному алгоритму Маркова.

Программа имитатора считывает схему и слово для применения со стандартного ввода
и печатает ПРОТОКОЛ вычислений на стандартный вывод.


Формат входных данных
=====================

Все строки, кроме последней, не содержащие биграммы "->" игнорируются.
Строки могут содержать комментарии от биграммы "//" до конца строки.
Последняя строка перед концом ввода рассматривается как слово, к которому
программа попытается применить схему алгоритма.

Значащими строками являются строки с биграммой "->".

Символы слева от этой биграммы представляют ЛЕВУЮ часть продукции.
Символы справа от этой биграммы представляют ПРАВУЮ часть продукции.

ПРОБЕЛЫ программа игнорирует.

Если ПОСЛЕДНИЙ символ значащей строки является символом "x", то продукция
помечается как ЗАВЕРШАЮЩАЯ подстановка.
Сам символ "x" в правую часть продукции не входит.

Пустое слово слева или справа задается как отсуствие значащих символов без особых знаков.

Продукции задаются в порядке приоритета от более к менее приоритетным сверху вниз.

Пример задания схемы и слова для обработки:

=== НАЧАЛО ЛИСТИНГА ===============================================
// Удвоение в унарном коде из |
// * - вспомогательный символ

*| -> ||*  // Удвоение |
* -> x     // Завершающая подстановка, чтобы не удвоить удвоенное
-> *       // Ставим * в начале строки

// Пример: удвоить 3 символа |

|||||
=== КОНЕЦ ЛИСТИНГА ================================================

В протокол программа выводит:
1. Листинг схемы после удаления комментариев и пробелов с добавлением
   новых пробелов для выравнивания.
   Правила (продукции) при этом НУМЕРУЮТСЯ от 1.
   
2. Воспринятое слово для применения.

3. Протокол пошаговых вычислений.
   На каждой итерации печается с новой строки
   3.1 Начальное слово или результат предыдущей итерации.
   3.2 На следующей строке ЛЕВАЯ часть применяемой продукции с пробелами слева
       для отступа, показывающего МЕСТО применения замены в строке слова вверху.
   3.3 НОМЕР правила в схеме согласно листинга в начале вывода.
   3.4 Правая часть соответсвующей продукции.
   
4. В конце работы печается причина завершения работы:
   ***__NO_MORE_RULES__*** - для завершения по отсутсвию смжных слов (тупик).
   ***__FINAL_RULE__***    - если применено завершающее правило
   ***__OVERFLOW__***      - если в результате замены получилось слово длинее макимально
                             допустимого в программе (255 символов).
   После этого печатается слово, полученное в результате применения последней итертации.
   Это и есть результат применения алгоритма, если не произошло переполнение строки.
   
Пример листинга вывода

=== НАЧАЛО ЛИСТИНГА ===============================================
  1 : *| -> ||*
  2 : * ->  x
  3 :  -> *

--- : |||||

|||||
 -3-> *
*|||||
*| -1-> ||*
||*||||
  *| -1-> ||*
||||*|||
    *| -1-> ||*
||||||*||
      *| -1-> ||*
||||||||*|
        *| -1-> ||*
||||||||||*
          * -2-> 
***__FINAL_RULE__***

||||||||||

=== КОНЕЦ ЛИСТИНГА ================================================

В примере правило 3 это вставка - левая часть пустая.
Правило 2 это завершающая подстановка. Поэтому после его применения
программа завершается.


Файлы
=====

na.dpr -- исходный текст программы на языке Object Pascal.
na.exe -- результат ее построения под платформу Win32 x86.

Файлы *.txt -- примеры исходных данных и листингов вывода.


Работа с программой
===================

Программа запускается в подсистеме консольного приложения.
Например, под управлением командного интерпретатра Windows типа cmd.

На других платформах можно использовать среду Wine 32 bit или комбинированную
Wine 32/64 с командным интерпретатором.

Программу можно запукскать интерактивно.
Тогда она ожидает построчного ввода в указаном формате.
После последней строки следует сформировать условие конца ввода
(конца файла). Например, на многих платформах это сочетание Ctrl+D.
Далее следует вывод и программа завершается.

Удобнее запускать программу с ПЕРЕНАПРАВЛЕНИЕМ потоков ввода-вывода.

Пример для большинства командных интерпретаторов:

na < input_file.txt > output_file.txt

В этом случае условие конца ввода формируется автоматически.

ВНИМАНИЕ:

Для построенного варианта (na.exe) данные должны быть оформлелены в виде
файлов в 8-битной кодировки, а строки разделяться ПАРОЙ симолов
ПЕРЕХОД_К_НАЧАЛУ_СТРОКИ (код 13), ПЕРЕХОД_НА_СЛЕДУЮЩУЮ_СТРОКУ (код 10).
Это стиандартный режим для Winows 8-битных текстовых файлов.

Специальыне символы программы "-" ">" "x" "/" должны иметь кодировку ASCII (ANSI).
Остальные символы - любую.
